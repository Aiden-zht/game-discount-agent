# 修复循环

## 4.1 流程

```
Agent B 返回审查报告（23 项完整报告）
        |
        v
BLOCKING 数量 = 0？
    +-- YES -> 进入发布（第 5 节）
    +-- NO  -> Agent A 修复
                |
                v
         修复后重新提交 Agent B
                |
                v
         循环计数 +1
                |
                v
         循环计数 >= 3？
            +-- YES -> 降级发布
            +-- NO  -> 继续修复
```

## 4.2 修复规则

- **传递完整审查报告**：Agent A 收到的是 Agent B 的完整 23 项审查报告（不仅是 BLOCKING 项），让 A 理解 B 的判断逻辑
- Agent A 只修复 BLOCKING 项，WARNING 项可选修复
- 每轮修复后，Agent B 重新检查所有项（不仅是修复项）
- 修复不能引入新的 BLOCKING 问题

## 4.3 修复时的 prompt 注入

```python
def build_fix_prompt(review_report, current_content):
    """构建修复 prompt，传递完整审查报告"""
    
    # 摘要：哪些是 BLOCKING，哪些是 WARNING
    blocking_items = [i for i in review_report["items"] if i["status"] == "BLOCKING"]
    warning_items = [i for i in review_report["items"] if i["status"] == "WARNING"]
    passed_items = [i for i in review_report["items"] if i["status"] == "PASS"]
    
    prompt = f"""请修复以下文章的 BLOCKING 问题。

## 审查报告摘要
- BLOCKING（必须修复）：{len(blocking_items)} 项
- WARNING（建议修复）：{len(warning_items)} 项
- PASS：{len(passed_items)} 项

## BLOCKING 项详情（必须修复）
"""
    for item in blocking_items:
        prompt += f"- [{item['code']}] {item['detail']}\n"
    
    prompt += "\n## WARNING 项详情（可选修复）\n"
    for item in warning_items:
        prompt += f"- [{item['code']}] {item['detail']}\n"
    
    prompt += f"""
## 当前文章内容
{current_content[:3000]}

## 要求
1. 修复所有 BLOCKING 项
2. 尽量修复 WARNING 项
3. 修复后不能引入新的 BLOCKING 问题
4. 保持文章整体风格和质量
"""
    
    return prompt
```

## 4.4 图片修复专项

当修复循环的 BLOCKING 涉及图片问题时（A9-A12 / B21-B23），按以下优先级处理：

### 4.4.1 图片重试流程

```python
def fix_image_issues(review_report, state):
    """图片问题修复：按成本从低到高尝试"""
    image_issues = [i for i in review_report["items"] if i["code"] in ("A9", "A10", "A11", "A12", "B21", "B22", "B23")]
    if not image_issues:
        return state
    
    # 检查哪些图片 FAILED
    failed_images = [img for img in state["images"] if img["upload_status"] == "FAILED"]
    
    for img in failed_images:
        # 1. 重试上传（最多 2 次）
        result = upload_with_validation(get_token(), img["source_url"])
        if result["status"] == "SUCCESS":
            img["upload_status"] = "SUCCESS"
            img["cdn_url"] = result["url"]
            img["retry_count"] += 1
            continue
        
        # 2. 尝试降级（按 P0→P4 优先级）
        fallback = apply_fallback(img, state["images"])
        if fallback:
            img["upload_status"] = "FALLBACK"
            img["cdn_url"] = fallback["url"]
            img["fallback_used"] = True
            continue
    
    # 重新生成 HTML（替换 CDN URL）
    state["content"] = rebuild_html_with_images(state["content"], state["images"])
    return state
```

### 4.4.2 降级策略（修复循环专用）

| 场景 | 处理方式 |
|------|---------|
| 某张截图 FAILED，有其他截图 | 从 HTML 中移除该 `<img>` 标签，HTML 其余部分不变 |
| 封面图 FAILED | 使用预设的占位封面图（永久素材，预先上传到微信 CDN） |
| 某款游戏的全部配图 FAILED | 从 HTML 中移除该游戏卡片区块，同步从 state JSON 的 games[] 中删除该条目 |
| B24 检查：某款推荐游戏无配图（无 WeChat CDN 图片） | **移除该游戏**：从 state JSON 的 games[] 列表和 HTML 中同时移除该游戏卡片区块。配图来源：游戏截图 → 胶囊图 → 母游戏截图（5 级降级策略在 Phase 1 已完成），若 Phase 1 后仍然无图则确认无法获取，直接移除 |
| 标题/推荐语中引用了配图描述 | 同步修改文字，删除对已移除图片的引用 |

## 4.5 降级发布

3 轮修复后仍有 BLOCKING 时：

1. **BLOCKING 项为标题党/敏感词等严重问题** → 跳过该篇，不发布
2. **BLOCKING 项为技术性（配图缺失/HTML 格式）** → 按 4.4 降级策略处理后发布剩余合格部分
3. **BLOCKING 涉及封面图且无法修复** → 跳过该篇（封面图缺失严重影响体验），记录失败原因
4. 在 state JSON 中记录 `{"degraded": true, "degrade_reason": "...", "degraded_images": ["header_01", ...]}`
5. 发布后人工审核确认
6. 记录到操作备案
