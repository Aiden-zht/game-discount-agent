# 图片治理规范

> 解决 Steam 折扣文章中图片"总是漏"的问题。定义从采集到发布的完整图片治理流程。
> 必须配合 [[业务/写作/公众号/创作规范/公众号发布流程与质量规范/02-AgentA-内容开发]] 和 [[业务/写作/公众号/创作规范/公众号发布流程与质量规范/03-AgentB-质量审查]] 一起使用。

---

## 1. 图片获取规范（数据采集阶段）

### 1.0 主题匹配原则

配图必须服务文章主题，不能因为历史模板、上一次任务、默认素材库或项目目录名称而套用无关图片。

| 文章类型 | 允许配图 | 禁止配图 |
|----------|----------|----------|
| 游戏折扣/游戏推荐 | 对应游戏 header、截图、胶囊图、官方素材 | 与推荐游戏无关的截图；AppID 不匹配的图片 |
| 知识库治理/Agent 工作流/技术方法论 | 架构图、流程图、信息图、抽象封面、界面截图（需与正文概念相关） | 任意游戏封面、Steam header、游戏截图 |
| 工具/脚本教程 | 工具界面截图、流程图、命令行截图、示意图 | 与工具无关的娱乐素材 |
| 复盘/观点文章 | 与核心观点相关的信息图、结构图、抽象视觉 | 仅因素材易得而加入的无关图 |

强制规则：

- 非游戏主题文章不得使用游戏封面、Steam header、游戏截图作为封面或正文图。
- 配图选择前必须先判断文章主题；若无法找到主题相关图片，优先使用无图排版、结构图或信息图，不得借用游戏素材填充。
- 若文章主题是“知识库治理”“Agent 协作”“流程规范”“系统设计”，优先使用流程图/架构图/信息图；没有合适图时可以不配图，但必须保持排版完整。
- 推荐类文章“必须配图”的规则仅适用于游戏折扣/商品推荐/内容推荐等强视觉场景，不自动扩展到治理类、方法论类、复盘类文章。

### 1.1 Steam 图片获取标准

| 图片类型 | 来源 | 分辨率要求 | 用途 |
|---------|------|-----------|------|
| 封面图（header） | Steam Store Header Image | ≥ 900×383 px | 文章封面，对应 `thumb_media_id` |
| 游戏截图（screenshot） | Steam API `screenshots` 字段 | 至少 1920×1080 | 正文内容配图 |
| 胶囊图（capsule） | Steam Store Capsule | 至少 616×353 px | 备选封面/卡片缩略图 |

### 1.2 图片获取红线

| # | 规则 | 违反后果 |
|---|------|---------|
| I1 | **下载超时必须有重试**：每张图片至少重试 2 次（间隔 3s），全部失败才标记为失败 | 直接跳过导致缺图 |
| I2 | **下载后校验文件完整性**：文件大小 > 0 bytes，非空文件 | 空文件占用资源 |
| I3 | **下载失败必须记录原因**：记录到 state.json 的 `images[].download_error` 字段 | 无法追溯失败原因 |
| I4 | **禁止用未下载的占位 URL 替代**：不允许在 HTML 中写入尚未确认可访问的图片 URL | 发布后图片显示裂图 |

### 1.3 图片与游戏的绑定规则

每张图片必须通过 `game_id`（Steam AppID）明确绑定到对应游戏，禁止图片与游戏不对应：

| # | 规则 | 违反后果 |
|---|------|---------|
| I5 | **每张图片必须标注所属游戏**：state.json 中每张图片必须有 `game_id` 和 `game_name` 字段 | 无法追溯图片归属 |
| I6 | **图片就近插入原则**：游戏 A 的截图必须插入游戏 A 的卡片区块内，不可放到其他游戏区块 | 读者混淆游戏画面 |
| I7 | **Steam 抓取时保留 AppID 映射**：从 Steam API 抓取截图时，保留 `appid` → `screenshots` 的对应关系，不混用 | 多游戏批量抓取时串图 |
| I8 | **封面图独立标注**：封面图（header）可以不属于任何游戏，标注 `game_id: "__cover__"` | 封面为整体文章服务，不属于单款游戏 |

## 2. 图片上传验证规范（内容生成阶段）

### 2.1 上传流程

```
图片下载完成
     ↓
格式/大小校验 → 不合格则标记 FAILED
     ↓
上传到微信 CDN（upload_material / upload_image_for_article）
     ↓
验证返回：media_id 非空 + URL 可访问（HTTP HEAD 200）
     ↓
写入 state.json images 数组
```

### 2.2 上传验证标准

| 检查项 | 方法 | 必须通过 |
|--------|------|---------|
| media_id/URL 非空 | 微信 API 返回值非空 | 是 |
| URL 可访问性 | `httpx.head(url)` 返回 200 | 是 |
| 文件格式 | 仅允许 jpg/jpeg/png/gif | 是 |
| 文件大小 | ≤ 10MB（微信限制） | 是 |
| 图片数量 | ≤ 20 张/篇（微信限制） | 是 |

### 2.3 上传失败处理

```python
UPLOAD_RETRY = {"max_attempts": 2, "interval_seconds": 5}

def upload_with_validation(token, image_path):
    """上传图片并验证结果，返回上传状态"""
    for attempt in range(UPLOAD_RETRY["max_attempts"]):
        try:
            result = upload_material(token, image_path)
            if result.get("media_id"):
                # 验证 URL 可访问性
                if verify_url_accessible(result.get("url", "")):
                    return {"status": "SUCCESS", "media_id": result["media_id"], "url": result.get("url")}
            errcode = result.get("errcode", 0)
            if errcode == 40001:  # token 过期
                token = refresh_token()
                continue
        except Exception as e:
            if attempt == UPLOAD_RETRY["max_attempts"] - 1:
                return {"status": "FAILED", "error": str(e)}
            time.sleep(UPLOAD_RETRY["interval_seconds"])
    return {"status": "FAILED", "error": "max retries exceeded"}
```

## 3. State JSON 图片字段扩展

每张图片的完整记录必须包含：

```json
{
    "images": [
        {
            "id": "screenshot_01",
            "game_id": "730",              # Steam AppID，封面图用 "__cover__"
            "game_name": "Counter-Strike 2",  # 游戏名称，用于校验
            "type": "header | screenshot | capsule",
            "source_url": "https://steamcdn.akamaihd.net/steam/...",
            "cdn_url": "https://mmbiz.qpic.cn/...",
            "upload_status": "SUCCESS | FAILED | FALLBACK",
            "upload_error": "下载失败/上传超时/media_id为空/文件过大",
            "retry_count": 2,
            "fallback_used": false
        }
    ]
}
```

### 3.1 上传状态语义

| 状态 | 含义 | 能否用于 HTML |
|------|------|-------------|
| `SUCCESS` | 上传成功且验证通过 | 可以 |
| `FAILED` | 上传失败且无可用降级 | 不可以 |
| `FALLBACK` | 原图失败，使用了降级图片 | 可以（有降级标记） |

## 4. 图片降级策略

### 4.1 降级层级

当某张图片上传失败时，按以下优先级降级：

| 优先级 | 方案 | 适用场景 |
|--------|------|---------|
| P0 | **游戏官方 CDN 直链**（Steam CDN 直连，不做上传） | 仅限已确认 Steam CDN 在国内可访问的域名 |
| P1 | **同类图片替代**（用胶囊图替代截图） | header 失败用 capsule，screenshot 失败用另一张截图替代 |
| P2 | **移除该图片**，但不影响其他图片 | 多张截图中某张失败，移除后仍有其他配图 |
| P3 | **整段移除**（如果某款游戏的配图全部失败） | 该游戏卡片完全无图，从推荐列表中移除该款 |
| P4 | **使用占位图**（统一的无图占位图） | 封面图必须存在时使用占位图 |

### 4.2 封面图强制规则

- **封面图（thumb_media_id）不允许降级为 P3（空）**，必须至少 P4（占位图）
- 如果所有降级方案均失败，阻断发布，进入修复循环
- 占位图应预先上传到微信 CDN 作为永久素材，`thumb_media_id` 硬编码在配置中

### 4.3 封面图选择标准

封面图直接决定读者是否点开文章，必须评估**购买诱惑力**而非单纯按好评率/折扣排序：

- **选择优先级（综合评分）**：
  1. **折扣力度 × 好评率 × 知名度权重**：高折扣 + 高好评 + 知名 IP > 低折扣 + 高好评
  2. **视觉冲击力**：游戏截图/海报的视觉吸引力（大制作画面 > 像素风 > 文字界面）
  3. **品类多样性**：避免封面和正文推荐第一名的品类相同（如封面是 FPS，正文第一名也是 FPS 就重复了）
  4. **限时紧迫感**：有明确截止时间的限时折扣比永久折扣更有吸引力
- **不选的典型情况**：独立小游戏（知名度低、画面简单）、纯文字界面游戏、好评率低于 70%
- **评分示例**：生化危机 4（75%折扣 × 97%好评 + 知名 IP）> 饥荒（90%折扣 × 85%好评但独立游戏）— 前者购买诱惑力更高
- 封面图必须为已上传至微信 CDN 的游戏截图（非占位图、非 Steam 直链）

### 4.4 推荐游戏配图强制规则

- **正文中每一款推荐游戏必须有配图**。任何游戏若无法获取至少 1 张配图（经过所有降级策略后仍然无图），必须从推荐列表中移除，不得以无图状态进入正文推荐
- 配图优先级：游戏截图（screenshot）> 胶囊图（capsule）> 母游戏截图（appdetails screenshots）
- 配图必须经过微信 CDN 上传成功后方可写入 HTML（非占位图、非 Steam 直链）
- 简版折扣列表中的游戏不适用本规则，纯文字表格无图是正常行为
- 本规则由 Agent B 的 B24 检查项强制执行，不通过则 BLOCKING，进入修复循环

### 4.4 降级记录

每次降级必须在 state.json 中记录：
```json
{
    "fallback_log": [
        {"image_id": "header_01", "original_error": "上传超时", "fallback_type": "P1-同类替代", "fallback_source": "capsule_01"}
    ]
}
```

## 5. 图片质量检查标准（Agent B 扩展）

Agent B 在原 B6 之外，新增以下图片相关检查：

| # | 检查项 | 规则 | 严重级别 |
|---|--------|------|----------|
| B21 | **配图上传成功率** | `FAILED` 状态的图片占比 < 50% | BLOCKING |
| B22 | **配图分布密度** | 正文每 400 字至少有 1 张配图（含封面），纯文字段落不超过 4 段 | WARNING |
| B23 | **图片-游戏映射准确性** | 每张非封面图（game_id != `__cover__`）必须：1) game_id 非空 2) HTML 中该游戏的卡片区域前后 200 字符内至少出现 1 张该 game_id 的图片 | BLOCKING |
| B24 | **每款推荐游戏必须有配图** | 正文中每一款推荐游戏（简版折扣列表除外）必须至少有 1 张已上传至微信 CDN 的配图（非占位图、非 Steam 直链），配图来源：游戏截图 > 胶囊图 > 母游戏截图（5 级降级策略仍适用） | BLOCKING |
| B28 | **配图主题匹配** | 非游戏主题文章不得使用游戏封面、Steam header、游戏截图；知识库治理/Agent 工作流/技术方法论类文章配图必须是流程图、架构图、信息图、界面截图、抽象视觉，或选择无图排版 | BLOCKING |

### 5.1 B6 升级

原 B6（图片数量）严重级别从 **INFO 升级为 WARNING**，确保 Agent B 至少关注图片数量问题。

## 6. 图片治理的红线清单

| 红线 | 违规后果 |
|------|---------|
| HTML 中不可出现 `src=""` 或 `src="待上传"` 等占位文本 | 阻断发布 |
| 不可直接将 Steam CDN URL 写入微信文章 HTML（微信端无法访问） | 阻断发布 |
| 封面图（thumb_media_id）不能为空或无效 | 阻断发布 |
| 单篇正文图片不可超过 20 张 | 超过则截断至 20 张 |

## 7. 数据反馈中的图片指标

发布后采集数据时，新增图片相关 KPI：

| 指标 | 计算方法 | 目标 |
|------|---------|------|
| 图片成功率 | SUCCESS 图片数 ÷ 总图片数 × 100% | ≥ 95% |
| 降级率 | FALLBACK 图片数 ÷ 总图片数 × 100% | ≤ 10% |
| 配图密度 | 正文图片数 ÷ 正文总字数 × 1000 | ≥ 2.5 张/千字 |

## 8. 游戏名显示规范

### 8.1 命名标准

文章中每款游戏必须呈现为**标准双语格式**：`{英文名} / {中文名}`，不允许以下任何情况：

| # | 违规类型 | 示例 | 违反后果 |
|---|---------|------|---------|
| N1 | **无中文名**：name_cn 等于 name_en 或为空 | `FINAL FANTASY VII REBIRTH` | 读者无法快速识别游戏，中文读者体验差 |
| N2 | **中文名混入英文**：name_cn 中重复出现 name_en | `DAVE THE DIVER / 潜水员戴夫 DAVE THE DIVER` | 信息冗余，格式混乱 |
| N3 | **纯英文无中文**：Steam API 返回仅英文名 | `R.E.P.O.` | 读者无法识别中文游戏名 |
| N4 | **显示空值**：`/ ` 或 `/` 后无内容 | `Resident Evil 4 /` | 明显错误，阻断发布 |

### 8.2 标准格式

```
英文全名 / 中文译名
```

- 英文名取 Steam API `appdetails?l=english` 的 `name` 字段
- 中文名取 Steam API `appdetails?l=schinese` 的 `name` 字段
- 中文名中若已包含英文副标题（如 Steam 中国区 store 返回的 "潜水员戴夫 DAVE THE DIVER"），应截取纯中文部分作为 cn_name，不保留重复英文
- 英文名中若包含中文（如拼音游戏 "DAVE THE DIVER"），保留英文原名，cn_name 使用中文译名

### 8.3 翻译降级链路

当翻译 API 不可用时，按以下顺序获取中文名：

1. **Steam API 直译**：`appdetails?l=schinese` 的 `name` 字段（通常为 Steam 中国区官方中文名）
2. **FALLBACK_TRANSLATIONS 兜底表**：steam_scraper.py 中的硬编码表，优先补全
3. **Steam 直链**：仅当 name_cn 完全为空且无法通过上述方式获取时使用英文名，但需在日志中标记 `name_cn_missing`

### 8.4 质量检查

Agent B 审查时新增检查项：

| # | 检查项 | 规则 | 严重级别 |
|---|--------|------|---------|
| B25 | **name_cn 非空检查** | `name_cn` 必须非空且至少包含 1 个中文字符；**例外**：若游戏在中文社区已有广泛认知且 Steam 官方也未提供中文名（如 R.E.P.O.、Gorilla Tag），可纯英文显示，但须在日志标记 `name_cn_unavailable` | BLOCKING |
| B26 | **name_cn 不含重复英文** | `name_cn` 中不得出现与 `name_en` 完全相同的字符串（忽略大小写） | BLOCKING |
| B27 | **显示格式完整性** | HTML 中每款游戏的名称展示区不能出现 `/ ` 或 `/` 后无内容的情况 | BLOCKING |

**B25 豁免判断**：当满足以下全部条件时允许纯英文名：
1. Steam API `l=schinese` 返回的 `name` 字段无中文字符（即官方未提供中文名）
2. FALLBACK_TRANSLATIONS 兜底表中该游戏的中文名 = 英文名（即手动标记为"无中文译名"）
3. 该游戏已有配图（图片已上传至微信 CDN）

### 8.5 当前兜底翻译表（必须维护）

`steam_scraper.py` 的 `FALLBACK_TRANSLATIONS` 表必须覆盖 cron 实际抓到的所有游戏名。每次 cron 运行后若发现新增游戏无中文名，应立即补入。

**维护责任人**：每次 cron 出现翻译失败游戏时，由发现者补入表并 push。
